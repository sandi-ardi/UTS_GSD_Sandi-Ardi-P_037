3. Jenis graf pertemanan yang dibuat
Kode: MERGE (a)-[:KNOWS]->(friend)
Hasil: Arthur -> Guinevere, Arthur -> Lancelot, Arthur -> Merlin.
Jenis graf:
 - Berarah (directed)  : relasi KNOWS punya arah (a)->(friend),
                         tidak simetris.
 - Tak berbobot        : relasi tidak punya properti bobot.
 - Homogen             : satu label (Person) dan satu tipe relasi
                         (KNOWS).
 - Bentuk star (bintang): Arthur sebagai hub dengan derajat keluar 3,
                         tanpa siklus.
 - Model data          : labeled property graph.

6. Proyeksi mana yang lebih baik (efektif/efisien)?
Perbandingan kuantitatif (dari output kode):

                         User-User   Item-Item
 Jumlah simpul             82.958      51.788
 Sisi (batas atas)        439.309     548.743
 Simpul terisolasi         22.670      27.839
 % terisolasi               27,33%      53,76%
 Median derajat vektor       1,00        1,00

Keterangan: sisi (batas atas) dihitung dengan d(d-1)/2 per simpul
perantara, sehingga merupakan batas atas.

Pembahasan:
 - Simpul    : Item-Item lebih sedikit (51.788 vs 82.958).
 - Sisi      : User-User lebih sedikit (439.309 vs 548.743). Sisi
   Item-Item membengkak kemungkinan karena segelintir user dengan
   interaksi sangat banyak (heavy user/bot); hal ini bisa diatasi
   dengan memfilter user tersebut sebelum proyeksi.
 - Terisolasi: User-User lebih baik (27,33% vs 53,76%). Pada Item-Item
   banyak item long-tail hanya disentuh user yang hanya berinteraksi
   dengan satu item.
 - Bukti per vektor: seri (median derajat sama-sama 1).

Kesimpulan:
Proyeksi Item-Item dipilih untuk perhitungan similarity berikutnya,
dengan pertimbangan:
 1. Jumlah simpul lebih sedikit (matriks lebih ringkas).
 2. Kegunaan: similarity antar-item bersifat lebih stabil/tahan lama,
    dapat disimpan sebagai relasi SIMILAR_TO pada graf dan dipakai
    ulang untuk semua user.
 3. Bukti per vektor setara dengan proyeksi User-User.
Kelemahan yang perlu dicatat: sisi (batas atas) lebih banyak dan
persentase simpul terisolasi lebih tinggi (53,76%), sehingga
cakupan similarity untuk item long-tail rendah. Jadi unggulan
Item-Item terutama pada kegunaan dan jumlah simpul, bukan pada
seluruh kriteria efisiensi.


7. Similarity pada graf terproyeksi
Item acuan: item dengan interaksi terbanyak, yaitu Item 187946.

(a) CYPHER untuk 5 record similarity tertinggi (Jaccard):

   MATCH (i1:Item {itemId: $ref_id})<-[:VIEWED|ADDED_TO_CART|BOUGHT]-(v:Visitor)
         -[:VIEWED|ADDED_TO_CART|BOUGHT]->(i2:Item)
   WHERE i1 <> i2
   WITH i1, i2, count(DISTINCT v) AS common_visitors
   MATCH (i1)<-[:VIEWED|ADDED_TO_CART|BOUGHT]-(v1:Visitor)
   WITH i1, i2, common_visitors, count(DISTINCT v1) AS visitors_i1
   MATCH (i2)<-[:VIEWED|ADDED_TO_CART|BOUGHT]-(v2:Visitor)
   WITH i1, i2, common_visitors, visitors_i1, count(DISTINCT v2) AS visitors_i2
   WITH i1, i2, common_visitors,
        (visitors_i1 + visitors_i2 - common_visitors) AS union_visitors
   WITH i1, i2, (1.0 * common_visitors / union_visitors) AS similarity_score
   ORDER BY similarity_score DESC
   LIMIT 5
   MERGE (i1)-[s:SIMILAR_TO]->(i2)
   SET s.score = round(similarity_score, 4)
   RETURN i1.itemId AS ItemAcuan, i2.itemId AS ItemMirip,
          s.score AS SimilarityScore

 Penjelasan: mencari item i2 yang dikunjungi visitor yang sama dengan
 item acuan i1; menghitung visitor bersama (irisan), jumlah visitor
 tiap item, lalu Jaccard = irisan / gabungan. Diurutkan menurun,
 diambil 5 teratas.

 Hasil (Top 5 Jaccard):
   ItemAcuan  ItemMirip  SimilarityScore
      187946     133549           0,0061
      187946     181852           0,0031
      187946      36956           0,0031
      187946      57245           0,0031
      187946     372855           0,0030

 Validasi dengan Python (matriks VSM Item, Jaccard biner):
   nilai Jaccard Cypher = nilai Jaccard Python -> konsisten (True).
 Pembanding cosine (vektor berbobot, L2):
   Top-5 Cosine: 181852 (0,0526), 101050 (0,0483), 133549 (0,0344),
                 57245 (0,0322), 372855 (0,0126).
 Catatan: Jaccard dan cosine memberi urutan berbeda karena cosine
 memakai bobot interaksi, sedangkan Jaccard hanya ada/tidaknya.
 Nilai keduanya kecil, mencerminkan data yang sangat sparse.

(b) Penulisan kembali nilai similarity ke graf:
   MERGE (i1)-[s:SIMILAR_TO]->(i2) SET s.score = round(similarity_score, 4)
 membuat relasi SIMILAR_TO beserta properti score di Neo4j. Properti
 cosine ditambahkan dengan:
   UNWIND $rows AS p
   MATCH (a:Item {itemId: p.ref})-[r:SIMILAR_TO]->(b:Item {itemId: p.item})
   SET r.cosine = round(p.cosine, 4)
 Bukti hasil query (relasi tersimpan di graf):
   MATCH (i1:Item {itemId: 187946})-[s:SIMILAR_TO]->(i2:Item)
   RETURN i1.itemId AS source, i2.itemId AS target, s.score AS score
 mengembalikan 5 relasi seperti tabel di atas.

2. Evaluasi metrik (Top-5 rekomendasi)
Ground truth (item aktual user di P2 yang belum ada di riwayat P1),
11 item:
   104800, 119460, 260488, 182445, 175600, 89042,
   176630, 215992, 362202, 63547, 351516
Top-5 rekomendasi:
   229940, 334401, 34532, 392898, 346673

(a) Hit@5
   Hit@5 = 1 jika ada minimal satu rekomendasi top-5 yang ada pada
   ground truth, selain itu 0.
   Vektor hit per rank (1..5) = [0, 0, 0, 0, 0]
   Hit@5 = 0,0000

(b) NDCG@5
   DCG@5  = sum( rel_i / log2(i + 1) ), i = 1..5 = 0,0000
   IDCG@5 = 1/log2(2) + 1/log2(3) + 1/log2(4) + 1/log2(5) + 1/log2(6)
          = 1 + 0,6309 + 0,5 + 0,4307 + 0,3869 = 2,9485
   NDCG@5 = DCG@5 / IDCG@5 = 0 / 2,9485 = 0,0000

Interpretasi:
 Tidak ada rekomendasi top-5 yang cocok dengan item aktual di P2,
 sehingga Hit@5 dan NDCG@5 bernilai 0. Hasil ini berasal dari satu
 user saja sehingga belum mewakili kualitas model secara umum.
 Faktor yang berpengaruh: data sangat sparse (sparsity 99,9973%),
 riwayat user hanya 5 item, kemiripan dengan tetangga rendah
 (cosine 0,26 - 0,44), dan perilaku user dapat berubah antar periode.
 Untuk evaluasi yang lebih andal sebaiknya dirata-ratakan pada
 banyak user dan dibandingkan dengan baseline popularitas.
